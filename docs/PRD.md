# 声场 VoxCast · MVP 产品需求

## 1. 一句话定义

将一段中文小说自动拆成旁白与角色台词，生成可解释的角色与配音方案；用户完成少量纠错后，一键生成多角色试听片段。

## 2. 为什么值得做

单一声线即使足够自然，也会把人物对白和叙事压成同一种表演。现有 TTS 解决“怎么把字念得像人”，声场解决的是：

- 这句话是谁说的；
- 这个角色应该是什么声音；
- 同一角色如何跨片段保持一致；
- AI 不确定时，人如何低成本纠错；
- 如何把多个片段稳定生成并拼成成片。

核心创新是“文本理解 → 自动选角 → 人工校正 → 多声线合成”的工作流，不是重新训练一个语音基础模型。

## 3. 目标用户

### 第一目标

- 有合法文本的网文作者和独立创作者；
- 想把自己的故事快速做成试听样片的人；
- 制作有声书、广播剧前需要预演角色的人。

### 第二目标

- 有无障碍阅读需求、希望人物更容易区分的读者；
- 出版社或音频工作室的前期配音策划。

## 4. MVP 成功标准

- 从粘贴文本到播放多角色试听能完成一条端到端路径。
- 原创演示文本中包含旁白和至少三类人物声线。
- 每个角色显示特质、证据、置信度和声线。
- 用户能改一条台词的说话人并立刻重新试听。
- 无 Key 时可演示；有 Key 时可生成真实 WAV。
- 自动化测试全部离线通过。
- 仓库和浏览器端不存在 API Key。

## 5. 用户故事

### US-01：导入文本

作为创作者，我可以粘贴一段小说，看到字符限制和支持的对话格式。

验收：

- 空文本不能提交；
- 超限文本在请求前后都有保护；
- 原文不被模型改写。

### US-02：自动识别

作为创作者，我希望系统区分旁白与台词，并告诉我每句台词最可能属于谁。

验收：

- 每个 segment 有稳定 ID、原文位置、类型和说话人；
- 低置信度不会被隐藏；
- 无法确定时允许“待确认角色”。

### US-03：自动选角

作为创作者，我希望系统根据文本证据给角色选择不同声线。

验收：

- 角色层的年龄、性别呈现、气质与台词层情绪分开；
- LLM 只输出语义标签，不直接编造供应商 voice ID；
- 确定性选角器只使用当前模型兼容的音色。

### US-04：人工纠错

作为创作者，我可以修改角色资料、声线与某句台词的说话人。

验收：

- 修改台词说话人后置信度视为人工确认；
- 角色名变化同步到台词下拉框；
- 修改后的数据直接用于试听和导出。

### US-05：试听与生成

作为创作者，我可以先免费试听，再决定是否消耗真实 TTS 额度。

验收：

- 浏览器试听不需要 Key；
- 真实生成前显示字符数并确认可能产生费用；
- 任一 provider 错误都会明确失败，不输出伪装完整的成品；
- 完成后提供播放器和 WAV 下载。

## 6. 不在 MVP 范围

- 账号、充值、订单与支付；
- EPUB/PDF 解析和整本书任务；
- 跨章节角色记忆；
- 语音克隆和公众人物仿声；
- 小说网站抓取；
- 背景音乐、环境音、自动混音；
- 对所有隐含对白宣称 100% 正确。

## 7. 非功能要求

- 可解释：人物推断保留证据和置信度。
- 稳定：外部模型失败时，本地基线仍可用。
- 安全：Key 只在服务端；文本不会进入代码日志。
- 可替换：LLM、TTS 与 UI 通过模块边界解耦。
- 可测试：核心逻辑不依赖网络。
- 版权：只允许自有、授权或公版文本。
