# 声场 VoxCast · 0.4 Book Project Alpha 产品需求

## 1. 一句话定义

一个面向中文普通用户的 AI 多人朗读器：上传小说后自动完成角色识别、音色分配、长期一致性管理和音频生成。

## 2. 为什么值得做

单一声线即使足够自然，也会把人物对白和叙事压成同一种表演。现有 TTS 解决“怎么把字念得像人”，声场解决的是：

- 这句话是谁说的；
- 这个角色应该是什么声音；
- 同一角色如何跨片段保持一致；
- AI 不确定时，人如何低成本纠错；
- 如何把多个片段稳定生成并拼成成片。

核心创新是“文本理解 → 自动选角 → 极简纠错 → 多声线合成”的工作流，不是重新训练一个语音基础模型，也不是把一组 API 参数直接暴露给用户。

用户不需要知道什么是 TTS、Token、SSML、音频轨道、角色标签或供应商模型。产品负责选择、重试、缓存、拼接和失败恢复。

## 3. 目标用户

### 第一目标

- 想上传自己的小说、剧本或文档直接听的普通读者；
- 有合法文本的网文作者和独立创作者；
- 想把自己的故事快速做成试听样片的人；
- 制作有声书、广播剧前需要预演角色的人。

### 第二目标

- 有无障碍阅读需求、希望人物更容易区分的读者；
- 出版社或音频工作室的前期配音策划。

## 4. MVP 成功标准

- 从粘贴文本到播放多角色试听能完成一条端到端路径。
- 原创演示文本中包含旁白和至少三类人物声线。
- 每个角色显示特质、证据、置信度和声线。
- 用户能改一条台词的说话人并立刻重新试听。
- 用户能纠正一个多音字，并让同一规则自动应用到全书。
- 用户能只重新生成改过的一句，其他句子不重复处理。
- 无 Key 时可演示；有 Key 时可生成真实 WAV。
- 自动化测试全部离线通过。
- 仓库和浏览器端不存在 API Key。

## 5. 用户故事

### US-01：导入文本

作为创作者，我可以粘贴一段小说，看到字符限制和支持的对话格式。

验收：

- 空文本不能提交；
- 超限文本在请求前后都有保护；
- 原文不被模型改写。
- TXT 支持 UTF-8、UTF-16、GB18030；
- 编码无法识别或控制字符异常时在分析前拒绝。

### US-02：自动识别

作为创作者，我希望系统区分旁白与台词，并告诉我每句台词最可能属于谁。

验收：

- 每个 segment 有稳定 ID、原文位置、类型和说话人；
- 低置信度不会被隐藏；
- 无法确定时允许“待确认角色”。

### US-03：自动选角

作为创作者，我希望系统根据文本证据给角色选择不同声线。

验收：

- 角色层的年龄、性别呈现、气质与台词层情绪分开；
- LLM 只输出语义标签，不直接编造供应商 voice ID；
- 确定性选角器只使用当前模型兼容的音色。

### US-04：人工纠错

作为创作者，我可以修改角色资料、声线与某句台词的说话人。

验收：

- 修改台词说话人后置信度视为人工确认；
- 角色名变化同步到台词下拉框；
- 修改后的数据直接用于试听和导出。
- 可编辑别名并把重复角色合并；
- 可编辑台词文本与情绪；
- 人工修改显示 `locked`，刷新页面后可从本机草稿恢复；
- 原文变化后，旧分析结果不能继续生成音频。

### US-05：试听与生成

作为创作者，我可以先免费试听，再决定是否消耗真实 TTS 额度。

验收：

- 浏览器试听不需要 Key；
- 真实生成前显示字符数并确认可能产生费用；
- 任一 provider 错误都会明确失败，不输出伪装完整的成品；
- 完成后提供播放器和 WAV 下载。
- 生成前显示未缓存字符、请求数与可选费用估算；
- 重复生成未变化片段不再调用 provider；
- 单段失败后保留成功缓存，可只重试失败片段；
- ffmpeg 可用时提供 MP3。

### US-06：全书发音纠正

作为读者，我发现人名或多音字读错后，只想纠正一次。

验收：

- 可从某句选中文字后建立“原词 → 朗读写法”规则；
- 规则随本机项目草稿保存；
- 浏览器试听、生成计划、内容缓存和真实语音都使用纠正后的朗读文本；
- 页面与 manifest 仍保留原文；
- 长词优先匹配，替换结果不会再次触发另一条规则。

### US-07：只重做一句

作为读者，我修改某句的角色、文字、情绪或发音后，不想重新生成整章。

验收：

- 每句提供“重做这句”；
- 服务端只接收并生成指定 segment；
- 未变化句子的缓存和音频不受影响；
- 新句子进入统一内容缓存，随后生成全书时可直接复用；
- 付费服务仍需在生成前确认预计字符和费用。

### US-08：隐藏技术复杂度

作为普通用户，我只想上传、试听、纠错和播放，不想选择技术组件。

验收：

- 默认分析方式是“自动（推荐）”；
- 主流程不出现 TTS、Token、SSML、provider、请求数或音频轨道；
- 模型、格式和离线诊断进入高级设置；
- 主生成计划使用“句子、字数、已准备、预计费用”等用户语言。

### US-09：导入整本 EPUB

作为普通读者，我希望直接导入一本合法 EPUB，再按章节处理，不需要自己复制每一章。

验收：

- 读取书名、作者和 spine 阅读顺序；
- 脚本、样式、导航和空页面不进入正文；
- 超长章节自动拆到单章分析限制内；
- 非 EPUB、损坏、越界路径、异常压缩、加密或 DRM 文件在分析前拒绝；
- 章节切换前自动保存文字、分析与纠错。

### US-10：跨章节保持人物一致

作为读者，我希望同一人物在后续章节继续使用已经确认的声音。

验收：

- 明确姓名或已知别名匹配时使用同一书级角色 ID；
- 后续分析不能覆盖人工锁定的角色类型与声音；
- 旁白之外最多保留 10 位主要角色；
- 超出上限的台词保留，并归入可手动调整的“其他角色”；
- 项目备份导入 / 导出保留章节、角色、发音记忆和人工纠错。

## 6. 不在 MVP 范围

- 账号、充值、订单与支付；
- PDF 解析和扫描件 OCR；
- 自动把所有隐含代词跨章强制合并为人物；
- 全书后台生成队列与边生成边播放（0.5）；
- 语音克隆和公众人物仿声；
- 小说网站抓取；
- 背景音乐、环境音、自动混音；
- 对所有隐含对白宣称 100% 正确。

## 7. 非功能要求

- 可解释：人物推断保留证据和置信度。
- 稳定：外部模型失败时，本地基线仍可用。
- 安全：Key 只在服务端；文本不会进入代码日志。
- 可替换：LLM、TTS 与 UI 通过模块边界解耦。
- 可测试：核心逻辑不依赖网络。
- 版权：只允许自有、授权或公版文本。
