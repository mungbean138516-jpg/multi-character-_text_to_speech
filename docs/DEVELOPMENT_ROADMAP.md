# 开发路线、版本验收与团队分工

## 当前进度（0.3 Consumer Alpha）

`0.1 MVP` 与 `0.2 Alpha` 已合并到 `main`。`0.3` 开始把“开发者工作台”收敛为普通读者会用的软件：

- [x] TXT 导入与 UTF-8 / UTF-16 / GB18030 检测；
- [x] 嵌套引号堆栈解析；
- [x] 千问 alias 数据合同、人工别名与角色合并；
- [x] 角色 / 台词人工修改的浏览器本机持久化；
- [x] TTS 内容哈希缓存；
- [x] 部分失败保留成功缓存，重新提交时只调用失败片段；
- [x] 生成前显示未缓存字符、请求数、可选预算上限；
- [x] WAV 与可选 MP3 输出。
- [x] 默认自动选择角色分析方式，模型选择收进高级设置；
- [x] 角色卡突出系统判断、默认声音、试听和更换；
- [x] 从任意一句开始试听、倍速与当前说话人提示；
- [x] 每句提供“角色错了”“这个字读错了”“重做这句”；
- [x] 全书发音词典，朗读替换不改显示原文；
- [x] 单句生成 API，未变化句子不重复处理；
- [x] 请求数、缓存、provider 与诊断音移出普通用户主流程。

仍需团队实测的不是“有没有按钮”，而是中文角色识别准确率、纠错耗时、真实账单误差和不同机器上的声音表现。

## 产品北极星

> 上传一本小说，自动变成多人朗读。

普通用户只需要理解六个动作：上传、识别、试听、换声音、纠错、开始生成。TTS、Token、模型、SSML、请求数和音频轨道只能出现在高级设置或开发文档中。

首版范围冻结为：

- 中文 TXT 与 EPUB；
- 旁白加最多 10 个主要角色；
- 20–30 个经过中文试听筛选的声音，而不是无限音色库；
- 自动识别、角色试听、换声音和保存角色配置；
- 单句角色纠错、全书发音纠正和单句重新生成；
- 第一章生成后即可播放，不等待全书完成；
- 不做背景音乐、多轨编辑器、声音克隆和影视级音效。

## 接下来的版本顺序

### 0.4 · 整本书基础

1. EPUB 解析：目录、章节、正文和编码校验；
2. 项目 JSON 导入 / 导出，保留原文、角色、别名、声音、人工锁定与发音词典；
3. 跨章节 `CharacterRegistry`，统一“李总 / 老李 / 李建国 / 父亲 / 他”；
4. 主要角色上限与次要角色降级策略：旁白 + 最多 10 位主要角色；
5. 将声音目录扩至 20–30 个中文精选音色，并完成模型兼容回归；
6. 章节级准确率评测集与错误类型表。

验收：导入一本合法 EPUB 后，关闭并重新打开项目，主要人物的别名、声音和人工纠正不丢失。

### 0.5 · 边生成边播放

1. 后台任务队列按章节、句子生成；
2. 第一章或首批句子完成后立刻允许播放；
3. 章节进度、暂停、继续和失败恢复；
4. 单句版本号与原子替换：修改后播放器只替换该句；
5. 相邻同角色短句合并，减少供应商调用；
6. WebVTT / LRC 时间轴和章节播放器。

验收：长篇任务不必等待全书；中途刷新页面后能恢复进度，修改一句不会重新生成整章。

### 0.6 · 多供应商与质量控制

1. 增加第二家中文 TTS adapter；
2. 建立 provider capability matrix：语言、情绪、速率、商业授权、区域和价格；
3. 为角色保存“声音特征档案”，供应商切换时匹配最接近音色；
4. 超时、限流、熔断和自动降级；
5. 漏读、空音频、响度、采样率和串台检查；
6. 用户纠错日志只记录结构化差异，不记录密钥。

验收：主供应商不可用时任务可安全暂停或切换，不把失败音频当作完整成片；切换后主要角色仍可区分。

### 1.0 · 消费产品

1. 登录、云端项目和对象存储；
2. 平台积分、生成前预授权、成功后结算、失败释放；
3. 用量账本、免费额度、成本仪表盘和缓存淘汰；
4. 版权声明、删除与导出、数据区域选择；
5. 第三方 TTS 商业输出 / 再分发条款台账；
6. PWA 或移动端封装。

正式版默认使用平台统一 Key，用户购买应用积分，不需要理解 Token；BYOK 只作为高级选项。

## 先说结论

现场 MVP 的边界应当是：

> 一段中文小说 → 自动角色初稿 → 人工确认 → 多声线试听 / WAV。

不要在 1–2 天里做整本书、账号、付费、声音克隆和复杂混音。评委会更看重一条少而稳定的真实链路。

## 第 1 周：从 Demo 到 Alpha

以上代码项已在 `0.2 Alpha` 完成。实现取舍：

- 持久化先使用当前浏览器 `localStorage`，不提前引入账号系统；
- 重试通过内容哈希缓存实现：重新提交同一项目时，成功片段直接命中缓存，只请求失败片段；
- 人民币费用只在配置当前供应商单价后估算，默认不硬编码易过期价格；
- MP3 使用 ffmpeg，WAV 管线仍可在纯 Python 环境运行。

验收指标：

- 明确归属台词 speaker accuracy；
- 对话边界 F1；
- 同角色声线一致率 100%；
- 失败片段可单独恢复；
- 1,000 字估算成本与实付误差可解释。

### 0.2 发布前数据验收

| 指标 | 最小样本 | 负责人输出 |
|---|---:|---|
| 明确说话人准确率 | 100 句原创 / 授权对话 | 错误类型表 + accuracy |
| 对话边界 F1 | 50 段，含嵌套与未闭合引号 | 标注 JSON + precision / recall |
| 缓存一致率 | 20 段重复生成 | provider 新调用数应为 0 |
| 失败恢复 | 人为让第 2 段失败 | 第 1 段命中缓存，仅重试第 2 段 |
| 成本误差 | 3 个百炼真实小任务 | 预估字符、控制台实付、差异说明 |

## 旧版第 2–4 周计划的状态

以下事项已重新编入上面的 `0.4–0.6`，仍按顺序做，不同时铺开：

1. EPUB 章节解析与项目 JSON 导入 / 导出；
2. 跨章节角色档案与 alias 图谱；
3. 人工 `locked` 跨章节生效，后续模型不能覆盖；
4. 相邻同角色短句合并，减少 TTS 请求；
5. 后台任务队列、可视进度和中断恢复；
6. WebVTT / LRC 时间轴；
7. 第二家 TTS adapter 与自动降级；
8. 角色声线距离优化，避免主角听起来太像。

随后补齐：

- 专名拼音、数字和英文缩写的精细读法；
- 项目级对象存储和缓存淘汰；
- 章节级音频、封面与元数据。

## 研究方向

- 中文跨章共指消解；
- 角色身份图谱与别名聚类；
- “角色基线 × 当前情绪”的声学控制；
- 声线可区分度的向量优化；
- 角色归属、自然度、情绪匹配与连贯性联合评测；
- 经明确授权的声音复刻。

## 每轮发布验收

- 核心链路至少有一条真实端到端测试。
- 无 Key 模式仍能运行。
- 真实 provider 可被 mock，CI 不访问外网。
- 新模型 ID 只进入配置，不散落在业务代码。
- 仓库无密钥、无受版权保护的长篇示例、无真实用户文本。
- 低置信度能被用户发现并纠正。
- 普通用户主流程不出现 Token、SSML、provider、请求数或音频轨道。
- 任何人工纠正都能明确说明影响范围：本句、全章或全书。
