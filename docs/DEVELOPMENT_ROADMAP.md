# 开发路线、1.5 天冲刺与团队分工

## 当前进度（0.2 Alpha）

`0.1 MVP` 已合并到 `main`；第 1 周 Alpha 的代码项也已完成：

- [x] TXT 导入与 UTF-8 / UTF-16 / GB18030 检测；
- [x] 嵌套引号堆栈解析；
- [x] 千问 alias 数据合同、人工别名与角色合并；
- [x] 角色 / 台词人工修改的浏览器本机持久化；
- [x] TTS 内容哈希缓存；
- [x] 部分失败保留成功缓存，重新提交时只调用失败片段；
- [x] 生成前显示未缓存字符、请求数、可选预算上限；
- [x] WAV 与可选 MP3 输出。

仍需团队实测的不是“有没有按钮”，而是准确率、真实百炼账单误差和不同机器上的浏览器声音表现。

## 先说结论

现场 MVP 的边界应当是：

> 一段中文小说 → 自动角色初稿 → 人工确认 → 多声线试听 / WAV。

不要在 1–2 天里做整本书、账号、付费、声音克隆和复杂混音。评委会更看重一条少而稳定的真实链路。

## 1.5 天冲刺

### D1 上午：冻结范围与数据合同

- 确认原创演示文本和三类人物。
- 固定 `CharacterProfile` 与 `ScriptSegment`。

- 用 Qoder 生成测试清单和接口合同。
- 验收：CLI 能把示例拆成旁白与台词 JSON。

### D1 下午：核心系统与界面

- 完成明确发言句式。
- 完成角色卡、置信度、声线目录。
- 完成台词说话人纠错。
- 完成浏览器多人试听。
- 验收：不用 Key 也能完成现场主流程。

### D1 晚上：真实 API 与音频

- 接千问 JSON 增强。
- 接百炼非实时 TTS。
- 下载每段 WAV，统一参数后拼接。
- 加字符限额与付费确认。
- 验收：至少用真实 API 生成一次 30–45 秒缓存成片。

### D2 上午：稳定性与路演

- 跑离线测试与端到端测试。
- 保留一个“低置信度台词”展示人工纠错。
- 固定 Demo 操作序列。
- 完成 README、Qoder 记录与踩坑。
- 彩排 8 分钟路演，Demo 至少 2 分钟。

## 第 1 周：从 Demo 到 Alpha

以上代码项已在 `0.2 Alpha` 完成。实现取舍：

- 持久化先使用当前浏览器 `localStorage`，不提前引入账号系统；
- 重试通过内容哈希缓存实现：重新提交同一项目时，成功片段直接命中缓存，只请求失败片段；
- 人民币费用只在配置当前供应商单价后估算，默认不硬编码易过期价格；
- MP3 使用 ffmpeg，WAV 管线仍可在纯 Python 环境运行。

验收指标：

- 明确归属台词 speaker accuracy；
- 对话边界 F1；
- 同角色声线一致率 100%；
- 失败片段可单独恢复；
- 1,000 字估算成本与实付误差可解释。

### 0.2 发布前数据验收

| 指标 | 最小样本 | 负责人输出 |
|---|---:|---|
| 明确说话人准确率 | 100 句原创 / 授权对话 | 错误类型表 + accuracy |
| 对话边界 F1 | 50 段，含嵌套与未闭合引号 | 标注 JSON + precision / recall |
| 缓存一致率 | 20 段重复生成 | provider 新调用数应为 0 |
| 失败恢复 | 人为让第 2 段失败 | 第 1 段命中缓存，仅重试第 2 段 |
| 成本误差 | 3 个百炼真实小任务 | 预估字符、控制台实付、差异说明 |

## 第 2–4 周：多章与可复用项目

建议按下面顺序做，不要同时开工：

1. EPUB 章节解析与项目 JSON 导入 / 导出；
2. 跨章节角色档案与 alias 图谱；
3. 人工 `locked` 跨章节生效，后续模型不能覆盖；
4. 相邻同角色短句合并，减少 TTS 请求；
5. 后台任务队列、可视进度和中断恢复；
6. WebVTT / LRC 时间轴；
7. 第二家 TTS adapter 与自动降级；
8. 角色声线距离优化，避免主角听起来太像。

随后补齐：

- 发音词典、专名拼音与数字读法；
- 项目级对象存储和缓存淘汰；
- 章节级音频、封面与元数据。

## 研究方向

- 中文跨章共指消解；
- 角色身份图谱与别名聚类；
- “角色基线 × 当前情绪”的声学控制；
- 声线可区分度的向量优化；
- 角色归属、自然度、情绪匹配与连贯性联合评测；
- 经明确授权的声音复刻。

## 每轮发布验收

- 核心链路至少有一条真实端到端测试。
- 无 Key 模式仍能运行。
- 真实 provider 可被 mock，CI 不访问外网。
- 新模型 ID 只进入配置，不散落在业务代码。
- 仓库无密钥、无受版权保护的长篇示例、无真实用户文本。
- 低置信度能被用户发现并纠正。
