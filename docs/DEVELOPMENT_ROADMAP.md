# 开发路线、1.5 天冲刺与团队分工

## 先说结论

现场 MVP 的边界应当是：

> 一段中文小说 → 自动角色初稿 → 人工确认 → 多声线试听 / WAV。

不要在 1–2 天里做整本书、账号、付费、声音克隆和复杂混音。评委会更看重一条少而稳定的真实链路。

## 1.5 天冲刺

### D1 上午：冻结范围与数据合同

- 确认原创演示文本和三类人物。
- 固定 `CharacterProfile` 与 `ScriptSegment`。
- 画出端到端流程。
- 用 Qoder 生成测试清单和接口合同。
- 验收：CLI 能把示例拆成旁白与台词 JSON。

### D1 下午：核心系统与界面

- 完成明确发言句式。
- 完成角色卡、置信度、声线目录。
- 完成台词说话人纠错。
- 完成浏览器多人试听。
- 验收：不用 Key 也能完成现场主流程。

### D1 晚上：真实 API 与音频

- 接千问 JSON 增强。
- 接百炼非实时 TTS。
- 下载每段 WAV，统一参数后拼接。
- 加字符限额与付费确认。
- 验收：至少用真实 API 生成一次 30–45 秒缓存成片。

### D2 上午：稳定性与路演

- 跑离线测试与端到端测试。
- 保留一个“低置信度台词”展示人工纠错。
- 固定 Demo 操作序列。
- 完成 README、Qoder 记录与踩坑。
- 彩排 8 分钟路演，Demo 至少 2 分钟。

## 七人分工

| 角色 | 可见交付 | 当天验收 |
|---|---|---|
| 1. 组长 / 产品 | PRD、范围、看板、时间控制 | 没有新增失控功能 |
| 2. 文本算法 | 引号解析、发言动词、测试集 | 明确句式准确、无证据时保守 |
| 3. LLM / Prompt | 千问 JSON、别名与指代、降级 | 失败不拖垮 Demo |
| 4. TTS / 音频 | provider、WAV 下载与拼接 | 真实语音与离线模式都能跑 |
| 5. 前端 / 交互 | 角色卡、台词表、播放器 | 能改角色、能改说话人 |
| 6. 测试 / 演示 | 用例、固定数据、彩排 | 新机器从零启动成功 |
| 7. 文档 / 视觉 | README、截图、Qoder 留痕、PPT | 每个人贡献可见 |

每人都应在 Git 提交、Qoder Prompt、测试、页面或文档中留下可见贡献。

## 第 1 周：从 Demo 到 Alpha

- TXT 文件上传与编码检测。
- 真实嵌套引号解析。
- 角色别名合并。
- 角色 / 台词人工修改持久化。
- 供应商响应缓存。
- 失败片段单独重试。
- 生成前显示预估字符、调用数和预算上限。
- 输出 MP3。

验收指标：

- 明确归属台词 speaker accuracy；
- 对话边界 F1；
- 同角色声线一致率 100%；
- 失败片段可单独恢复；
- 1,000 字估算成本与实付误差可解释。

## 第 2–4 周：多章与可复用项目

- EPUB 章节解析；
- 跨章节角色档案与 alias 图谱；
- 人工修改 `locked`，后续模型不能覆盖；
- 发音词典、专名拼音与数字读法；
- 内容哈希缓存；
- 后台任务队列和进度；
- WebVTT / LRC 时间轴；
- 多供应商 adapter；
- 角色声线距离优化，避免主角听起来太像。

## 第 1–2 月：正式产品能力

- 登录、项目与对象存储；
- 应用内 credits 与用量账本；
- BYOK 高级设置；
- 配额、并发、退避重试；
- 数据区域选择、删除与导出；
- 内容审核与版权声明；
- 监控、告警和成本仪表盘；
- 移动端或 PWA。

## 研究方向

- 中文跨章共指消解；
- 角色身份图谱与别名聚类；
- “角色基线 × 当前情绪”的声学控制；
- 声线可区分度的向量优化；
- 角色归属、自然度、情绪匹配与连贯性联合评测；
- 经明确授权的声音复刻。

## 每轮发布验收

- 核心链路至少有一条真实端到端测试。
- 无 Key 模式仍能运行。
- 真实 provider 可被 mock，CI 不访问外网。
- 新模型 ID 只进入配置，不散落在业务代码。
- 仓库无密钥、无受版权保护的长篇示例、无真实用户文本。
- 低置信度能被用户发现并纠正。
