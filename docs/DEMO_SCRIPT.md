# 现场演示脚本（2 分 40 秒）

## 演示前

- 使用 Chrome 或 Safari。
- 启动 `python3 -m audiobook_app`。
- 新开无痕窗口走一遍完整路径。
- 若演示真实百炼，提前确认余额、Key、Workspace ID 和网络。
- 准备离线模式作为备用；不要把缓存结果说成实时生成。

## 0:00–0:20 · 痛点

讲：

> 现在很多听书产品已经能把文字念得很像真人，但旁白、少女、老人和小孩仍可能共享一条声线。问题不只是 TTS 自不自然，而是系统根本没有先理解“谁在说话”。

操作：停留在首屏，指向“小说不该只有一个声音”。

## 0:20–0:45 · 输入

操作：

1. 点击“载入原创演示文本”。
2. 快速滚动文本，指出其中有林夏、陈默、老爷爷和小男孩。
3. 点击“开始选角”。

讲：

> 这段文本完全原创，所以演示没有版权问题。系统先用规则抓取明确句式，再可选用千问解决复杂指代。

## 0:45–1:25 · 角色卡

操作：

1. 展示旁白与人物角色卡。
2. 指向证据和置信度。
3. 将一个 `unknown` 年龄或性别呈现改成正确值。
4. 替换一位角色的声线。

讲：

> 系统不会根据姓名硬猜性别。没有文本证据就显示未知，让创作者决定。LLM 只产出年龄、气质等语义标签，供应商 voice ID 由确定性选角器管理，避免模型编造不存在的音色。

## 1:25–1:55 · 台词纠错

操作：

1. 滚动到台词轨道。
2. 指出绿色、黄色和红色置信度。
3. 手动改一条台词的说话人。

讲：

> 全自动不可能永远正确，所以我们没有掩盖歧义，而是把人工纠错设计成主流程。改完这一行，试听和导出立即使用新结果。

## 1:55–2:20 · 多人试听

操作：点击“浏览器多人试听”，播放 15–20 秒，再停止。

讲：

> 这一步完全免费，不需要 API Key。浏览器会按角色使用不同的语速和音高，先让用户判断选角是否合适。

## 2:20–2:40 · 真实生成与收束

优先操作：点击“百炼真实合成”，确认费用提示，播放预先控制在 30–45 秒的结果。

断网备用：点击“生成离线链路检测音”，明确说明它是诊断音，只验证逐句生成、插入停顿、拼接和下载。

讲：

> 真实 TTS 使用百炼非实时 HTTP 接口，供应商的临时音频会被立即下载，再统一拼成 WAV。未来换其他 TTS，只替换 provider，不需要重做角色系统。

结束：

> 我们没有再造一个“更像人的朗读器”。我们给 TTS 补上了它缺失的导演层：先理解人物，再为每个角色选声。

## 答辩准备

### 为什么不用一个 LLM 直接输出整本书音频？

角色归属、人工修改、缓存、费用、失败重试和供应商替换都需要中间结构。直接一次生成不可解释，也无法只重做错误片段。

### 为什么还需要人工纠错？

小说常省略主语、使用别名和自由间接引语。承认不确定并让人快速修正，比强行猜错更像可用产品。

### 用户是否必须买 Token？

正式消费产品默认由平台统一付费，用户买应用积分；BYOK 只作为高级选项。课堂 MVP 由团队在服务端配置受限 Key。

### Qoder 帮了什么？

按真实记录回答：需求拆解、数据合同、代码骨架、规则测试、错误定位、README 和演示脚本。展示 Prompt 迭代，不要只说“让它写了代码”。
